# Browser wallet and marketplace UI continuation

2026-09-09, checkout `bnbera-ui-light`, base `3f98a015fd771c478114ae4997bcd1d11db701f1`.

The user's explicit request adds injected browser wallets alongside WalletConnect and supersedes the earlier WalletConnect-only connector restriction in the active MVP documents. The shell and hire flow share one wagmi provider. Named EIP-6963 providers (including MetaMask and Rabby) are separately selectable; a legacy EIP-1193 browser provider is offered only when present and no named provider has been discovered. WalletConnect retains its QR/mobile path when the public project ID is configured. Missing WalletConnect configuration does not disable extensions.

Discovery makes no connection/signature/payment prompt. Connection follows the selected button. The header exposes explicit BNB mainnet (56) and BNB testnet (97) switches; each agent states its actual hiring network and readiness. Account/network/disconnection changes invalidate the browser commerce authority and request server logout globally. An account/network change during an awaited SIWE challenge, signature or verification prevents the stale sign-in from becoming usable. Existing operations retain their exact actor/network/reconciliation checks.

The scoped visual refinement preserves the existing dark palette. Booking panels show the actual price explanation, chain, payment method, capacity and dated readiness; service cards use distinct capability identifiers/descriptions and declared protocols. Marketplace rows expose dated checks, advertised capability counts, actual latest-result summaries and remaining capacity when supplied. External directory rows keep vendor activity scores explicitly separate from task counts, and surface check times, service counts, unknown price and unavailable hiring. No metrics, reviews or task results were generated for this UI work.

Library behavior was checked against the installed wagmi 2.16.9 / core 2.20.3 source and official [configuration](https://wagmi.sh/react/api/createConfig#multiinjectedproviderdiscovery) and [injected connector](https://wagmi.sh/react/api/connectors/injected) documentation. This does not upgrade the pinned dependencies.

No commit, chain payment, reservation, provider restart or database mutation is required to verify this UI. The existing [bounded provider allowance](PROTOCOL-COMMERCE-REVIEW.md#three-slot-supervised-allowance-continuation) remains authoritative; never request a retained quote during UI testing. Production build/restart and final browser evidence are coordinated with the main agent.

## Acceptance and chain-aware continuation

Public preview browser checks at desktop 1440px and mobile 390px returned successful marketplace/reference pages with no JavaScript errors or horizontal overflow. Viewport captures are retained in `.runtime/protocol-commerce-review/ui-upgrade-{marketplace,reference}-{1440,390}.png`, plus `ui-upgrade-services-390.png`. An isolated clean mock EIP-6963 browser exposed MetaMask and Rabby separately alongside WalletConnect, selected Rabby only after its explicit button, switched 56→97 explicitly, reflected account changes, invalidated authentication and disconnected. Commerce requests were blocked and authentication endpoints mocked: this is connector integration evidence, not a real-wallet signature or paid mainnet acceptance.

SIWE now accepts chain 56 only with `BNBERA_ENV=preview`, `EXTERNAL_ERC8183_MAINNET_ENABLED=true`, the existing wallet-auth gate and a credential-free HTTPS application origin. Chain-97 defaults/preview restrictions and Altana chain-97 authentication remain unchanged. Nonces and sessions bind the exact account/chain/domain; closing the mainnet gate makes existing mainnet sessions unreadable. The journey threads the agent/activation chain into authentication, chain switching, public-client receipts, send requests and persisted quote checks. Target-chain changes invalidate the generation just as wallet changes do. A signed offer or payment-ready adapter does not imply verified execution.

The chain-aware continuation passed 35 focused web tests, web TypeScript and lint. The subsequent external-offer presentation adds two passing tests (37 focused web tests total): readable requested task, exact formatted quote price, experimental signed-offer / execution-unverified notice, seven-day dispute window and no automatic approval. Exact canonical contract task bytes remain expandable; no delivery or reconciliation buttons are introduced before their routes exist.

The corresponding chain adapter/encoder work passed the complete commerce package suite (111 tests) plus package TypeScript and lint. Mainnet reads require an explicit browser-preview option and process gate, strict runtime/implementation/token/linkage checks and the seven-day policy. All four server-side Altana writer entry points reject chain 56 even if a release flag is set. Package ownership returned to the parent for backend composition.

These newer chain-aware/quote changes require the next parent-coordinated production build before public browser acceptance; the screenshots above cover the preceding wallet/layout build.
